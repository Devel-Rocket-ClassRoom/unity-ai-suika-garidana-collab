# Issue #10 — 과일 단계별 크기 차이 부족

## 원인 분석

`FruitType.cs`의 `FruitDatabase`에서 `baseRadius=0.5f`, `sizeMultiplier=1.25f`를 사용하고 있었다.

| 단계 | 과일 | 반경(기존) | 지름(기존) | 컨테이너(10) 대비 |
|---|---|---|---|---|
| 1 | 체리 | 0.500 | 1.000 | **10.0%** |
| 2 | 딸기 | 0.625 | 1.250 | 12.5% |
| 11 | 수박 | 4.657 | 9.314 | **93.1%** |

체리가 이미 컨테이너 너비의 10%로 크고, 체리↔딸기 지름 차이가 0.25에 불과해 육안으로 구분하기 어려웠다.
또한 수박 지름이 컨테이너 너비(10)의 93%로 너무 커서 정상 플레이가 어려웠다.

---

## 수정 내용 — `Assets/Scripts/FruitType.cs`

```csharp
// 수정 전
float baseRadius = 0.5f;
float sizeMultiplier = 1.25f;

// 수정 후
float baseRadius = 0.25f;   // 체리 지름 = 0.5 (컨테이너의 5%)
float sizeMultiplier = 1.32f; // 각 단계 32% 증가
```

### 설계 근거

- **체리(5%)**: 화면에서 분명히 보이되 가장 작은 과일로 표현
- **단계당 1.32배**: 인접 단계 간 눈에 띄는 크기 차이 (기존 1.25배보다 명확)
- **수박(80.3%)**: 컨테이너 너비의 80% — 원작 수박게임 비율과 유사, 실제로 들어갈 수 있는 크기
- **체리→수박 비율**: 16.1배 (기존 9.3배 → 확대)
